# ADR-003: Pipeline de ingesta desacoplado del transporte externo

- **Estado**: Aceptado
- **Fecha**: 2026-10-04
- **Contexto**: Ingesta automatizada de transacciones y arquitectura de integracion
- **Decisores**: Equipo de Arquitectura de LuminaApp

## Contexto del Problema

Inicialmente, el sistema contemplaba una dependencia directa con flujos de trabajo de n8n para procesar transacciones de Yappy y notificaciones bancarias. Un acoplamiento estrecho con n8n convierte a dicha herramienta en un punto unico de fallo y dificulta la migracion futura a otros transportes, como webhooks directos de pasarelas, adaptadores de Open Banking o servicios serverless de procesamiento de correos.

## Decision

Se desacopla completamente el **dominio de ingesta** del **mecanismo de transporte**:

1. n8n es considerado exclusivamente un adaptador de transporte de eventos externos, al mismo nivel que un worker de correo, un script CLI o un webhook de agregador financiero.
2. El backend expone un puerto de entrada estandarizado (`Webhook Ingest Gateway`) con un contrato canonico agnostico del emisor.
3. El pipeline de procesamiento interno se organiza en etapas modulares e independientes:
   - Recepcion e Idempotencia
   - Persistencia de Evento Crudo (`RawEvent`)
   - Normalizacion de Descripcion y Comercio
   - Deduplicacion Multi-Nivel
   - Enriquecimiento y Categorizacion Heuristica
   - Publicacion a la Bandeja de Revision o Transaccion Confirmada
4. Cualquier cambio o sustitucion de n8n no afectara la logica de negocio, validaciones ni modelos de base de datos de LuminaApp.

## Consecuencias

### Positivas
- Alta resiliencia e intercambiabilidad de herramientas de automatizacion.
- Capacidad de procesar multiples fuentes simultaneas bajo la misma tuberia de reglas de negocio.
- Facilidad para probar unitariamente cada fase del pipeline sin simular instancias completas de n8n.

### Negativas / Mitigaciones
- Demanda definir contratos de interfaz y esquemas DTO canonicos intermedios rigurosos.
