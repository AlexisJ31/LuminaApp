# ADR-006: Bandeja de revision obligatoria para transacciones con nivel de confianza inferior a 0.85

- **Estado**: Aceptado
- **Fecha**: 2026-10-04
- **Contexto**: Experiencia de usuario y precision en la clasificacion de gastos
- **Decisores**: Equipo de Arquitectura de LuminaApp

## Contexto del Problema

La asignacion automatica y categorizacion de transacciones bancarias mediante expresiones regulares o modelos de clasificacion heuristica nunca alcanza un 100% de precision. Si una transaccion ambigua se inserta directamente como confirmada en una categoria incorrecta (por ejemplo, clasificar una compra de farmacia como ocio), el usuario pierde visibilidad y sus presupuestos se distorsionan sin su consentimiento explicito.

## Decision

Se define el flujo de **Bandeja de Revision (Inbox) Asistida**:

1. Toda transaccion procesada por vias automatizadas recibe un puntaje de confianza (`confidenceScore` entre 0.0 y 1.0).
2. Regla de clasificacion estricta:
   - Si `confidenceScore >= 0.85`: la transaccion puede transicionar a `REVIEWED` automaticamente si el usuario tiene activada la auto-aprobacion para ese comercio reconocido.
   - Si `confidenceScore < 0.85`: la transaccion se crea obligatoriamente en estado `UNREVIEWED` y genera un registro en la bandeja de revision (`ReviewItem`).
3. Las transacciones `UNREVIEWED` se presentan de manera prominente en el dashboard del usuario, permitiendo confirmacion con un solo clic, reasignacion de categoria o descarte.
4. Las transacciones `UNREVIEWED` se reflejan en el pacing engine con un indicador visual diferenciado para advertir que son gastos preliminares no conciliados.

## Consecuencias

### Positivas
- Control total del usuario sobre la exactitud de sus registros.
- Aprendizaje del sistema: cada revision manual del usuario retroalimenta la tabla de alias (`MerchantAlias`) para elevar la confianza futura.

### Negativas / Mitigaciones
- Demanda atencion periodica del usuario para vaciar su bandeja de entrada. Se mitiga disenando atajos de teclado rapidos (Enter para aprobar, Delete para rechazar) y acciones en lote.
