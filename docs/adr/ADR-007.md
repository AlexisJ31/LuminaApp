# ADR-007: Autenticacion y autorizacion derivadas exclusivamente de la sesion del servidor

- **Estado**: Aceptado
- **Fecha**: 2026-10-04
- **Contexto**: Seguridad, aislamiento multi-tenant y prevencion IDOR (Insecure Direct Object Reference)
- **Decisores**: Equipo de Arquitectura de LuminaApp

## Contexto del Problema

En controladores iniciales de prueba, se permitia la lectura opcional de `userId` desde el cuerpo de la peticion (`req.body.userId`) o desde parametros no autenticados (`req.query.userId || 'usr-1'`). Esto constituye una vulnerabilidad critica de tipo IDOR, permitiendo que un usuario malintencionado mutara o leyera las cuentas y transacciones de cualquier otro usuario alterando un identificador en el JSON de peticion.

## Decision

Se impone la regla de **Derivacion Estricta de Identidad desde el Token de Sesion**:

1. El backend nunca confia en campos `userId` o `accountId` provenientes del cuerpo de la peticion del cliente como afirmacion de autorizacion.
2. Todas las rutas privadas pasan por el middleware de autenticacion (`authMiddleware`), el cual valida criptograficamente la firma del JWT y la vigencia temporal.
3. El `userId` extraido del claim `sub` del token validado se inyecta en el objeto de solicitud (`req.user.id` / `req.userId`).
4. Cualquier consulta o mutacion a la base de datos (`findMany`, `create`, `update`, `delete`) incluye obligatoriamente la clausula `where: { userId }` derivada del servidor.
5. Se eliminan todas las asignaciones de fallback hacia identificadores estaticos como `'usr-1'` en el codigo de produccion.
6. Para webhooks autenticados por API Key y secreto HMAC, el `userId` se resuelve mediante la entidad `SourceConnection` asociada criptograficamente a la clave API.

## Consecuencias

### Positivas
- Erradicacion completa de vulnerabilidades IDOR en el acceso a datos financieros.
- Aislamiento estricto de inquilinos (multi-tenancy seguro).

### Negativas / Mitigaciones
- Las pruebas de integracion requieren generacion de tokens JWT validos o el uso de headers de prueba firmados y controlados exclusivamente en entorno de test.
