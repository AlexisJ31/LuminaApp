# ADR-002: Base de datos PostgreSQL con Prisma ORM como unica fuente de verdad

- **Estado**: Aceptado
- **Fecha**: 2026-10-04
- **Contexto**: Persistencia y consistencia de datos de LuminaApp
- **Decisores**: Equipo de Arquitectura de LuminaApp

## Contexto del Problema

Las fases iniciales de prototipado empleaban arreglos en memoria (`mockTransactions`, `mockAccounts`) y persistencia local de frontend (`localStorage`). Esta arquitectura no garantiza durabilidad ACID, impide la sincronizacion concurrente entre dispositivos, carece de transaccionalidad para transferencias entre cuentas y es vulnerable a perdidas de datos tras reinicios de servidor.

## Decision

Se establece **PostgreSQL administrado (via Supabase / RDS)** orquestado mediante **Prisma ORM** como la **unica fuente de verdad** para todos los datos de la aplicacion:

1. Queda terminantemente prohibido el uso de almacenamiento simulado en memoria (`mockTransactions`) en entornos de ejecucion de la API.
2. Todas las consultas de lectura y mutacion pasan por repositorios o servicios que interactuan con Prisma Client.
3. Las transferencias entre cuentas y la creacion de transacciones que afecten balances se ejecutan dentro de transacciones interactivas de Prisma (`prisma.$transaction`).
4. Las migraciones de base de datos se versionan estrictamente con Prisma Migrate y se auditan antes de cada despliegue.

## Consecuencias

### Positivas
- Cumplimiento de propiedades ACID (Atomicidad, Consistencia, Aislamiento y Durabilidad).
- Integridad referencial con claves foraneas e indices optimizados.
- Tipado estricto extremo generado por Prisma a lo largo de todo el backend TypeScript.

### Negativas / Mitigaciones
- Requiere configuracion de cadena de conexion (`DATABASE_URL`) y ejecucion de migraciones en entornos de CI/CD. Se mitiga mediante contenedores o bases de datos dedicadas para staging.
